Выпустить пакет для OpenWrt

Вы написали приложение LuCI или тему. Дальше — как её собрать, доказать, что она работает на живом роутере, подписать и положить туда, откуда её поставят одной командой apk add. Копируйте файлы, меняйте имена, готово.

Три инструмента

owlab

Одноразовые роутеры в Docker. Собрать пакет, поставить, проверить, что страница открывается.

owfeed

Подписать пакеты и написать подписанную опись релиза. Или держать целый фид.

owfeed-packages

Живой фид. Попросите взять ваш пакет — и у пользователей заработает apk upgrade.

Друг от друга они не зависят. Договорённость у них одна: каталог dist/, внутри — подкаталог на архитектуру. Всё, что заполняет его правильно, работает со всем остальным.

1. Собрать и проверить у себя

Нужен Docker. Больше ничего.

go install owfeed.org/owlab/cmd/owlab@latest

cd my-luci-app
owlab build --release 25.12.5      # настоящая сборка в SDK, пишет в dist/<arch>/
owlab up                            # поднять роутер
owlab install owrt2512 dist/*/*.apk
owlab open owrt2512                 # LuCI в браузере

Пока идёт работа, пересборку можно вообще пропускать:

owlab sync --watch    # копирует исходники в живой роутер на каждое сохранение

И вся проверка одной командой — она же крутится в CI:

owlab test --release 25.12.5 --release 24.10.8 \
  --install 'dist/*/luci-app-mine-*' \
  --assert 'http 200 /cgi-bin/luci/admin/services/mine'
Проверяйте обе ветки. На 25.12 пакетный менеджер apk, на 24.10 — opkg, и совпадают они почти ни в чём. Пакет, который работает на одной, может упасть на другой.

2. Что где лежит

ФайлЗачем
owlab.yamlКакие роутеры поднимать. Необязателен — флаги работают и без него.
MakefileВаш пакет, как его ждёт OpenWrt. owlab build читает именно его.
dist/<arch>/Собранные пакеты. Их пишет сборка и читает всё остальное.
.github/workflows/ci.ymlПроверка на каждый push.
.github/workflows/release.ymlПодпись и публикация по тегу.

Минимальный owlab.yaml, если он всё-таки нужен:

version: 1
routers:
  - id: owrt2512
    release: "25.12.5"
  - id: owrt2410
    release: "24.10.8"
Про dist/. Архитектурно независимый пакет попадает сразу в два каталога, и это правильно: apk называет такую архитектуру noarch, opkg — all, и каждый артефакт лежит там, как он сам себя называет. 
dist/
├── noarch/my-app-1.0.0-r1.apk
└── all/my-app_1.0.0-r1_all.ipk

3. GitHub Actions

.github/workflows/ci.yml

name: ci
on: [push, pull_request]
permissions: { contents: read }
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix: { release: ["25.12.5", "24.10.8"] }
    steps:
      - uses: actions/checkout@v5
      - uses: owfeed/owlab/setup@v0.3.0
      - run: owlab build --release ${{ matrix.release }}
      - uses: owfeed/owlab/action@v0.3.0
        with:
          releases: ${{ matrix.release }}
          install: dist/*/my-app-*
          assert: |
            package my-app
            http 200 /cgi-bin/luci/admin/services/mine

Ключей в этом job нет вообще — поэтому его безопасно гонять на pull request из форка.

.github/workflows/release.yml

name: release
on:
  push: { tags: ["v*"] }
permissions: { contents: read }
jobs:
  release:
    runs-on: ubuntu-latest
    permissions: { contents: write }
    steps:
      - uses: actions/checkout@v5
      - uses: owfeed/owlab/setup@v0.3.0
      - uses: owfeed/owfeed/setup@v0.1.5

      - run: owlab build --release 25.12.5
      - run: owlab build --release 24.10.8

      - name: Подписать и написать манифест
        env: { OWFEED_RELEASE_KEY: ${{ secrets.RELEASE_KEY }} }
        run: owfeed release --repo ${{ github.repository }} --tag ${{ github.ref_name }}

      - run: gh release create "${{ github.ref_name }}" --generate-notes
             dist/*/*.apk dist/*/*.ipk dist/manifest.txt*
        env: { GH_TOKEN: ${{ github.token }} }

Ключ делается один раз и кладётся в секреты репозитория:

owfeed keygen --usign -o release.key
gh secret set RELEASE_KEY < release.key
git add release.key.pub && git commit -m "the public half"
Публичную половину держите в репозитории. По ней кто угодно — и фид в том числе — проверяет, что релиз действительно ваш. Приватная не покидает секрет.

4. GitLab CI

Те же три команды, другой файл. Оба инструмента — один статический бинарь, ставить нечего:

build:
  image: docker:27
  services: [docker:27-dind]
  variables: { DOCKER_HOST: tcp://docker:2375, DOCKER_TLS_CERTDIR: "" }
  script:
    - wget -qO owlab https://github.com/owfeed/owlab/releases/latest/download/owlab-linux-amd64
    - wget -qO owfeed https://github.com/owfeed/owfeed/releases/latest/download/owfeed-linux-amd64
    - chmod +x owlab owfeed && export PATH="$PWD:$PATH"
    - owlab build --release 25.12.5
    - owlab test --release 25.12.5 --install 'dist/*/my-app-*'
  artifacts:
    paths: [dist/]

release:
  needs: [build]
  rules:
    - if: $CI_COMMIT_TAG
  script:
    - wget -qO owfeed https://github.com/owfeed/owfeed/releases/latest/download/owfeed-linux-amd64
    - chmod +x owfeed
    - export OWFEED_RELEASE_KEY="$RELEASE_KEY"
    - ./owfeed release --repo "$CI_PROJECT_PATH" --tag "$CI_COMMIT_TAG"

owfeed release сам подхватывает CI_PROJECT_PATH и CI_COMMIT_TAG, так что флаги выше — только ради явности.

5. Попасть в фид

Теперь пакет можно поставить из релиза. Чтобы у пользователей заработал ещё и apk upgrade, попросите owfeed-packages взять его к себе.

  1. Выпустите релиз с подписанным манифестом. Это шаг owfeed release выше. Фид проверяет его до того, как что-либо тронет.
  2. Откройте issue по шаблону Request package publication. Укажите репозиторий, тег, свой публичный ключ и его id.
  3. Бот проверит за минуту — что релиз существует, что манифест сходится с ключом, который вы называете своим, и что формат читаемый. Если что-то не так, он скажет что именно.
  4. Ключ смотрит человек. Это единственный ручной шаг, и обойти его нельзя: добавление ключа — и есть всё решение о доверии.
  5. Дальше автоматика. Каждый ваш новый тег подхватывается в течение часа и приезжает в фид без вашего участия.
Почему манифест важен. Есть манифест — обновления приезжают без человека. Нет, только файлы — каждое обновление ждёт человека, потому что подпись на файлах не говорит, какие файлы входят в релиз.

Проверить, что ставится из фида, а не только из файла

Когда пакет уже в фиде, эту проверку стоит завести. Установка файла доказывает, что работает пакет; установка по имени из подписанного индекса доказывает, что работает канал: индекс читается, URL не редиректит, ключ совпадает:

owlab test --release 25.12.5 \
  --feed 'https://repo.owfeed.org/releases/25.12/x86_64/packages.adb' \
  --feed-key ./owfeed-packages.pem \
  --install my-app \
  --assert 'http 200 /cgi-bin/luci/admin/services/mine'

6. Уже есть пакет на 24.10? Добавьте 25.12

Типичный случай: .ipk, который годами работает, и пользователи на 25.12, которые просят apk. Портировать ничего не нужно.

owlab build --release 25.12.5     # тот же Makefile, на выходе apk
owlab test  --release 25.12.5 --install 'dist/*/my-app-*'

Собралось и страница открывается — всё, публикуйте обе линии из одного релизного job, как в разделе 3. Обычно стоит проверить две вещи:

ЧтоПочему
conffilesКаждый /etc/config/*, который везёт пакет, обязан быть объявлен — иначе обновление затрёт настройки пользователя. apk относится к этому строже, чем opkg.
arch: allapk отвергает all как неустановимое. Пишите LUCI_PKGARCH:=all и дайте сборке перевести — так делает и собственная упаковка OpenWrt.

Если ваш пакет — тема, приложение, скрипт или статический бинарь, SDK не нужен вовсе: owfeed build пакует уже разложенный каталог за секунды, вместо того чтобы качать тулчейн.

7. Что делают пользователи

Когда пакет в фиде, вся инструкция выглядит так — её стоит положить в свой README:

# OpenWrt 25.12 и новее
apk add ca-bundle libustream-mbedtls
wget https://repo.owfeed.org/owfeed-packages.pem \
  -O /etc/apk/keys/owfeed-packages.pem
echo "https://repo.owfeed.org/releases/25.12/$(cat /etc/apk/arch)/packages.adb" \
  > /etc/apk/repositories.d/owfeed-packages.list
apk update && apk add my-app
Скажите им не ставить файл напрямую. apk add ./my-app.apk пишет в /etc/apk/world пин на хеш файла, пин переживает sysupgrade, и после этого пакет уже никогда не обновится из фида.
